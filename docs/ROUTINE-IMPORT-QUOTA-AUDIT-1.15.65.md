## Persistence change

The standalone browser keeps its existing synchronous authoritative `gym_state_v1` profile key and existing IndexedDB database `tgym-profile`. After an actual primary quota failure, supported large media (at least 32 KiB) is staged in the additive `resources` object store; SHA-256 identifies immutable content. The complete resource transaction must commit and a fresh read must verify its bytes before a compact profile containing references can be committed to localStorage. Only a successful primary profile write publishes the imported state and registers custom exercises. Runtime, native files, cloud data and portable exports keep hydrated original strings. Browsers whose original write fits keep the existing inline representation. Native Capacitor retains its prior localStorage/file persistence; a native WebView quota fallback is not claimed.

Schema 4 prevents older app versions from interpreting references as media or overwriting this representation. Existing schema 3 and earlier data remain readable. The original inline profile is never removed before resource verification and primary commit. A resource transaction failure aborts its writes; a later primary quota failure preserves the old core and in-memory state. Verified, unreferenced staged resources can remain after that failure and be reused on retry; no user resources, history or offline data are automatically deleted. Browser mirrors reuse references to avoid a second persisted copy of the same media.

Boot hydrates and verifies resources before exposing editable routes. Missing, damaged or inaccessible resources block editing and preserve the saved profile. A local technical recovery bundle retains the raw profile plus all readable referenced resources and identifies unavailable ones; it is labelled separately from a portable full backup. Retry reopens storage. No site-data clearing or reinstallation is required.

## Import and error behavior

Confirmation uses an awaited store transaction, rechecks current state, and prevents overlapping saves. Failures retain the import review and adaptation choices for Retry or Cancel. The UI distinguishes quota, file validation, read/access, conversion and other persistence failures, with localized recovery text. A collapsed technical section retains the original exception chain/stack, operation, backend, key/store, measured sizes, actual source/destination units and available runtime/version information. It contains no copied profile or embedded resource content. Spanish adaptation notices retain their original meanings. The general primary-save warning uses neutral language and does not infer that the device disk is full.

The JSON reader no longer labels an original file read/access exception as malformed JSON. Parser syntax failures remain validation failures with their original cause. No exercise, note, prescription, personal preference or unrelated routine is removed to fit the import.
