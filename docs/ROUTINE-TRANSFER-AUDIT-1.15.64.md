Status: local source acceptance, exact-source CI/signed candidate and physical Android acceptance/restoration passed; release1.15.64 is published and independently verified. ## Reproduction and corrected flow

The existing exchange flow was audited from export through real file download, file selection, validation, preview, reviewed apply, starting the imported routine and re-export. The authoritative transformation remains in the shared frontend, with one complete draft committed through `useStore.update`; the existing binary file adapter handles Excel/PDF save/share. Progress Report and arbitrary PDF import are outside this change.

With version-1 source and destination profiles using different defaults, a source prescription with Same Back-off, strict repetitions and 45-second rest became +2 Back-off, non-strict repetitions and 180-second rest after import. Superset and warm-up rests changed similarly. Excel/PDF also rounded Back-off using the progression increment instead of the exercise's load grid: a 100 kg Top, 14% reduction, 7.5 kg progression increment and 5 kg grid displayed 82.5 kg, whereas runtime prescribed 85 kg. Rest-pause displayed three Working sets of eight instead of the runtime activation set of eight and one Working target of fifteen total repetitions.

The original export included unused custom resources and unrelated metadata; a used resource could refer to a device-local `blob:` URL. Losing hidden Excel preservation data silently removed custom resource/configuration information, incompatible workbook versions could disagree, and modified ZIP checksums were accepted. These failures were reproduced before correction, rather than inferred from visual layout.

## Format and compatibility

New exports use exchange version 2. Source rules are complete and the effective per-exercise prescription is materialized in the transfer document: progression policy, independent load grid, strict repetitions, bodyweight mode, rests and automatic Back-off exception. Export does not mutate the source routine or copy results, historical next loads or destination-wide preferences. Prescribed loads transfer; subsequent progression still uses the destination's own history. Identical future progression is therefore conditional on equivalent relevant history, not promised across different training histories.

JSON and Excel retain original identities, order, repeated exercise instances, aliases, notes, schedules, supersets, fixed/ranged targets, unilateral work, all set roles and legacy independent/offset Back-off prescriptions. Legacy technical fields such as `tempo` remain metadata; preservation is not a claim that runtime currently applies them. Unsupported public configuration fields stop export with correction instructions instead of being silently dropped. Credential fields are excluded.

Version-1 exchange files and supported older plans remain readable. Missing source context requires an explicit adaptation acknowledgement; source/destination effort and enabled deload differences are disclosed instead of overwriting preferences. Personal deload calendars remain local. Unknown versions and incoherent workbook/metadata versions block import. Unit conversion is reviewed explicitly and preserves the load grid independently of progression; timed progression increments remain seconds. Version 2 with missing mandatory context is rejected rather than borrowing destination defaults silently.

The five visible workbook sheets remain compatible in purpose. Normal export includes the used custom definitions/resources once; the downloadable template additionally includes the complete real local catalogue. Catalogue selectors retain exact original IDs/names and distinguish duplicate names. Expanded data tables, frozen columns and validations remain available. Removing required version-2 preservation metadata for a used custom definition produces an actionable error. Workbook parser errors retain sheet, row and field locations. Corrupt archive CRCs are checked, and long Unicode preservation chunks are reopened without corruption.

Used custom definitions are validated against the current supported model. Embedded raster/GIF resources are structurally checked and bounded; safe absolute public HTTPS resources are allowed. Local paths, temporary/query-bearing URLs, credentials, unsupported SVG and `blob:`/`file:`/`content:` references are rejected with recovery instructions. Embedded resources support offline transfer; external HTTPS availability is not guaranteed and is not tested by a URL syntax check. Separate IDs and definitions are reviewed when the destination already has a different custom exercise. Copy/remapping reserves identities present in routines, history, active/resumable sessions, scheduling and other local references, including references whose original exercise was deleted.

Import validates before saving and reviews mapping, identity conflicts, duplicates, conversion and adaptations. Keeping, copying and replacing remain explicit; replacement requires confirmation. Cancel, invalid files, failed persistence and a changed destination after preview leave the profile unchanged. Import creates routine prescriptions, never completed workouts. The normal store update path remains in use: its pre-existing provenance normalization can add `sessionOrigin` to a legacy historical record that lacks both this field and a routine ID when routines change. Freezing that origin before import prevents a name-only legacy result from binding to a newly imported same-name routine. Existing historical values and counts are retained; exact byte equality for such legacy rows is not claimed.
