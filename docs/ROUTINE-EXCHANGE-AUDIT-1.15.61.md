# Routine exchange corrections - 1.15.61 / Android 97

## Reproduction and data flow

The audit starts from published 1.15.60, including its direct browser download correction. `RoutineExchange` prepares a local state snapshot; `routine-exchange.js` projects visible XLSX rows and preservation metadata, validates the entire file, builds one complete import draft and commits through `useStore.update`. Routine PDF uses its own page builder and the existing binary file adapter. History, active workouts, Progress Report, storage identifiers and native update checks remain outside this change.

New regression tests failed on the original code for decimal commas, whitespace-only rows, unrelated Series edits materializing inherited rest/Back-off preferences, legacy offset loss, malformed preservation data/identifiers, missing current prescriptions and performed-result fields, unrelated catalogue metadata applied to imports, keeping all routines still changing aliases, mapping revalidation, and incomplete portable rules/weight-step conversion. The old plan exporter omitted units, so its loads cannot safely be assumed to be kg. The UI also retained schedule/default choices from the previous file and showed only exercise/set counts. PDF used line-by-line pagination that could orphan headings and omitted readable intensity, side, strict-target and derived distance details.

## Result and compatibility

Format version remains 1; optional columns extend its existing headers. Earlier exact header prefixes and version-1 preservation metadata remain supported. New JSON includes optional deload settings in `rules`. No storage migration or historical rewrite is needed. Old plans without a unit require an explicit source kg/lb choice; units differing from the current profile also require conversion confirmation. Unsupported versions, changed headers, corrupt metadata and unsupported independent prescriptions block saving with correction instructions.

Excel keeps the five visible sheets and very-hidden preservation metadata. Native tables can grow; lists select the real catalogue (including all local custom definitions), routine IDs and unique exercise instances. Mandatory/editable/technical fields have distinct fills. Frozen identity columns, wrapped text, useful widths and numeric/list validation support authoring. Optional progression/rest/bodyweight/strict-rep/AMRAP/intensity fields and safe configuration JSON cover existing uncommon fields. No macros or lookup formulas identify exercises. A cell or metadata chunk respects Excel's 32767 UTF-16-unit limit. Numeric text accepts one decimal point or comma, with no grouping, currency, mixed separators or exponents; absent values remain absent.

Editing one field retains unrelated absent/inherited settings. Automatic Back-off targets derive from the edited Top and its existing rule; explicit legacy offsets and independent ranges survive. Import rejects results masquerading as prescriptions. Every referenced custom definition/alias/library note is limited to accepted routines. Exact built-in original names and IDs remain authoritative. Mapping never silently substitutes a movement or attaches unknown-ID aliases to another exercise. Duplicate IDs/names need reviewed keep/copy/replace decisions; replacement needs a second explicit acknowledgement. Cancel and invalid files make no writes.

Routine PDFs use readable A4 tables, measured wrapping, continuation headers, and heading-plus-content pagination. They show load/unit, bodyweight added load, unilateral prescriptions, RIR/rest, Top association, Back-off reduction/rule, progression and intensity instructions. Cardio distance is derived from the existing min/speed model, not a new independent parameter. Rest-pause presentation reuses the existing activation/work planner. Names respect presentation preference while JSON/XLSX retain original identity.

New unit suites exercise real serialized XLSX and JSON, simple/complex/multiple routines, repeated exercise instances, both automatic Back-off modes and legacy/manual exceptions, supersets, fixed/ranged reps/RIR, custom duplicate names, aliases, accents, unit conversion, timed/cardio prescriptions, malformed/incomplete/old/repeated files, mapping, cancellation and atomic drafts. Applicable frontend/API/MCP checks and final exact-source CI are recorded in the release audit.

Chromium/Edge and WebKit at mobile widths completed UI selection, all three direct downloads, full catalogue template, XLSX preview/replace/reimport, invalid-reference rejection, explicit unknown mappings and cancellation. Saved routines, ordered schedules, custom definitions, aliases and pre-existing synthetic history remained equal; no completed workout was created. WebKit is browser simulation, not a physical iPhone or native iOS build.

Representative and expanded PDFs were generated through the real Edge app builder, reopened and rasterized with PyMuPDF. Their 2/3 rendered pages have content. Visual review covered table hierarchy, continuation, accents/symbols, long notes, intensity and side/cardio cases; SVG layout regressions check measured text positions. The shared binary adapter rasterizes the PDF, so text extraction is not a blank-page test. XLSX structure, native validations/tables and round-trip content are reopened from actual saved bytes. Saved XLSX styles for all five sheets were reconstructed for browser visual review; this caught and corrected a clipped long header. Interactive Microsoft Excel inspection was stopped by the user's Escape key; no more native UI actions followed, so interactive Excel acceptance remains pending.
